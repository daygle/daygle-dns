# models/

Trained model artifacts shipped with Daygle DNS so the AI scanner
(`daygle-dns-ml`) works out of the box — a supervised fastText classifier
plus a MiniLM/ONNX verifying second pass for threat verdicts.

## daygle-starter.bin

A small supervised fastText domain-classification model (`.bin` format,
fastText `__label__<category>` label convention), trained with the pure-Rust
`fasttext` crate — the same inference library the server runs.

- **Provenance**: generated by `cargo run --release -p daygle-dns-ml --bin
  train-starter-model` from the curated dataset in
  [`starter-training.txt`](starter-training.txt). Self-supplied data: mostly
  well-known everyday domains plus pattern-based threat examples. No external
  corpora were downloaded.
- **Size budget**: dim 24, 50k character-n-gram buckets ⇒ a few MB. Real
  deployments are free to point `ai.model_path` at any larger `.bin`; this is
  a starter, not a finished model.
- **Categories**: `malware`, `phishing`, `gambling`, `adult`, `piracy`
  (threats) and `search`, `news`, `social`, `streaming`, `shopping`,
  `gaming`, `finance`, `education`, `developer`, `cloud`, `health`,
  `travel` (content). `malware`/`phishing`/`adult` are auto treated as
  threat severity; the auto-block category list is config
  (`ai.auto_block_categories`, default `["malware", "phishing"]`).
- **Safe by default**: installs ship with the AI scanner enabled in
  `train` mode — verdicts are recorded, nothing is blocked, until an
  operator flips `ai.mode` to `enforce` in the config or GUI. The starter
  model has not been audited against a threat-intel benchmark, so treat its
  enforce-mode verdicts like any other automation: watch the verdict log,
  allowlist generously.

## all-MiniLM-L6-v2-int8.onnx (verifier)

An int8-quantized ONNX export of [`all-MiniLM-L6-v2`](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)
(384-dimension sentence embeddings, ~23 MB), pulled from the
[`Xenova/all-MiniLM-L6-v2`](https://huggingface.co/Xenova/all-MiniLM-L6-v2)
transformation (model int8 ONNX + full BERT tokenizer pipeline shipped as
`minilm-tokenizer.json`).

- **License**: Apache-2.0 (sentence-transformers / ONNX export), used and
  redistributed under that license. Attribution: sentence-transformers
  (UKP Lab, TU Darmstadt); ONNX/quantized export by Xenova.
- **Role**: verifying second pass for *threat* verdicts. The fastText model
  stays the cheap primary; the verifier embeds `domain + title + text` and
  compares cosine similarity against per-category centroid embeddings. It
  corroborates agreements (confidence raise), vetoes confident
  disagreements (severity downgrade), and never runs on the DNS hot path.
- **Regeneration**: `cargo run --release -p daygle-dns-ml --bin
  gen-minilm-centroids` rebuilds `minilm-centroids.json` from
  `starter-training.txt` — the centroid file must be regenerated whenever
  the dataset's categories change.
- **Build note**: compiled and loaded via the `ort` crate (ONNX Runtime,
  feature `daygle-dns-ml/verifier-onnx`, on by default). Static musl
  release binaries build with `--no-default-features` because the prebuilt
  ONNX Runtime binaries are glibc-based; those builds run fastText/heuristic
  only, `verifier_model_path` is ignored there.

## Regenerating

```sh
cargo run --release -p daygle-dns-ml --bin train-starter-model
```

The tool expands each dataset line into www.-prefix / hyphen-joined /
space-joined tokenizer variants (matching how the backend feeds domains in),
trains with a fixed seed, probes a handful of held-out expectations, and
overwrites `daygle-starter.bin`. Commit both files together if the labels,
categories, or dataset change.
